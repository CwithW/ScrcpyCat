# 前端接口审计与连接设置修复

本次对照前端 HTTP 请求、WebSocket 消息、后端路由及 Agent 执行链检查，重点修复移植前端留下的字段不一致、仅本地生效和未落实的设置。本报告记录源码审计与隔离验证结果，实际部署版本以 Git 提交和生产镜像记录为准。

## 审计结果及处理

| 功能 | 发现的问题 | 处理 |
| --- | --- | --- |
| 设备标签 | 前端使用 `deviceTags`，后端使用 `device_tags`，分配关系保存不完整；保存失败缺少反馈 | 后端兼容两种字段，拒绝冲突输入，持久保存并按设备权限过滤；前端失败回滚并显示错误 |
| 单设备连接设置 | 主要保存在当前浏览器，没有对应的设备默认设置接口 | 新增 `GET /api/device_settings` 和 `GET/POST/PUT/DELETE /api/devices/{id}/settings`；管理员默认设置持久化、同步并下发 Agent；跨浏览器恢复默认会清理已同步的旧副本；普通用户仍可保存个人覆盖 |
| 保存并连接 | 改为等待后端保存后，弹窗提前关闭会清空设备 ID，造成只保存不连接 | 在开始保存时固定目标设备 ID，保存成功后再连接该设备 |
| 用户在线状态、控制中的设备 | 返回默认值，没有关联真实连接 | 按实时连接计算在线状态、去重汇总控制设备 |
| 注销 | 接口未真正撤销登录令牌 | 每次登录生成独立标识；持久撤销当前令牌，关闭该登录对应的连接并使其 WebSocket ticket 失效，保留其他登录 |
| 高级功能注入 | 未独立区分 GPS、传感器和剪贴板，缺少明确的能力响应 | 后端保留 `inject_data` 路由及多设备目标转发；Agent 返回能力错误，剪贴板保持可用 |
| GPS、传感器注入、浏览器摄像头透传 | 当前 Agent 不具备这些能力 | 按要求暂不实现；`gps_injection`、`sensor_injection`、`camera_injection` 均为 `false`，请求返回 `capability_error` 和 `supported: false`，不启动采集 |
| 保持设备唤醒 | 原方式依赖 scrcpy cleanup 和充电状态，Android 本机 Agent 的 `cleanup=false` 模式不可靠 | 改用随采集生命周期生效的 `keep_active`；连接和预览独立控制，不修改手机持久充电唤醒设置 |
| 连接参数 | 各入口映射不一致，部分值没有实际传至采集进程；零值限制、调试、相机方向、音源等存在偏差 | 统一参数映射；Agent 保留 `fps=0/size=0`，正确传递调试、音源、复制声音和方向参数 |
| 快照间隔 | 单设备设置没有独立下发，运行中更新不及时 | 合并全局与设备设置，下发 Agent 后立即更新；普通用户不能修改 Agent 的快照周期 |
| 预览与多观众 | 观众退出后没有可靠恢复剩余观众参数，唤醒或音频需求可能丢失 | 后端维护预览请求；Agent 合并观众需求，正式连接优先，退出后恢复剩余预览或连接，无观众则停止采集 |
| WebSocket 音视频 | 视频和音频参数、启动先后顺序可能造成重新启动 | 首次请求带齐音视频选项；停止后的采集不再提供旧参数，音频先到也使用新会话配置 |
| scrcpy profile | 先强制 profile，失败后回退会启动两次；实际编码与协商 profile 可能不一致 | 全局采用兼容配置，让 MediaCodec 首次选择 profile；从实际 SPS 配置 WebRTC SDP 和浏览器解码，保留显式 codec options |
| 预览解码 | 强制 Baseline 与兼容配置输出的 Main/High 不匹配；WASM 需要完整 access unit | Baseline 使用 WASM，Main/High 自动使用 WebCodecs；卡片和列表共用解码器，补充真实 H264 解码回归测试 |
| 分享页连接选项 | 传入的网络、渲染偏好可能被管理员浏览器本地设置覆盖 | 优先使用分享页传入的会话选项 |
| 网速显示 | 新旧 Agent 的 B/s 与前端 KiB/s 约定不一致 | 新 Agent 显式标记单位，后端兼容转换旧 Agent 数据，避免相差 1024 倍 |
| 高密列表菜单 | 被列表容器裁剪 | 菜单挂载到 `body`，按视口定位，支持贴边、滚动关闭和 Escape |
| 大盘趋势图 | 默认仅选告警设备或在线设备中的前三台，导致在线数量与趋势曲线数量不一致 | 默认展示全部在线设备，保留矩阵手动筛选；取消全部选择后恢复展示全部在线设备 |

已核对账号管理、设备分配、分享/卡密、任务、云端文件、设备文件、终端、截图、监控和部署入口的路由及执行链；这些功能已有实际实现。本次没有将演示模式的 mock、已存在云端文件的“上传完成”展示误判为后端 stub。

## 默认值与移动端展示

| 设置 | 默认行为 |
| --- | --- |
| 设备展示 | 高密列表 |
| 实时预览 | 关闭；开关保存在浏览器 `cloudphone_preview_enabled` |
| 连接时保持设备唤醒 | 开启 |
| 预览时保持设备唤醒 | 关闭 |

实现沿用现有存储、权限及信令机制；共用连接参数映射和预览解码器，避免各入口重复适配。媒体生命周期集中在 Agent 管理，对本次明确暂缓的三种能力只保留协议和能力响应。

验证脚本、原始 JSON 结果和列表截图位于本机 `/tmp/scrcpycat-settings-validation/`。单设备和单个 Chrome 版本的测试不能代替全部 Android 型号、编码器及浏览器的兼容性验证。

## 环境收尾

已停止测试 host/Android Agent、移除专用 ADB reverse、清理手机测试文件和本次安装的测试 APK。手机休眠时间恢复为 30000ms，充电唤醒恢复为 0，媒体音量恢复为 10。

隔离验证结束后，原生产容器已恢复运行，确认一个生产 Agent 进程及稳定的 WSS 连接，重启策略仍为 `unless-stopped`。测试后端、PostgreSQL、Redis、TURN 均已停止；其他验收环境未改动。该阶段尚未发布本次改动，生产恢复使用原镜像与身份配置。

专用 18443 SSH 转发已撤销，共用 SSH 连接未关闭；Chrome 保持运行。
